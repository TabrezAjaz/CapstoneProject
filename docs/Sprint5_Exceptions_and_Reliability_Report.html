2. Policy Flow

Trivy raw findings
  -> validate exact allowlist rules and UTC expiry
  -> active findings -> severity counts -> gate exit 0 / 1
  -> suppressed findings + reason + expiry -> audit evidence
  -> raw counts + policy checksum + rescan lineage
  -> strict report loader -> JSON / HTML / PDF / dashboard

Invalid configuration -> exit 2 before scanning
Operational error / retries exhausted / malformed output -> exit 3
Suppression is accepted risk, not remediation. Historical CVE/package comparisons include suppressed findings, so an approved vulnerability does not inflate the resolved metric.

3. Allowlist Contract

exceptions:
  - id: CVE-2026-40200
    image: alpine:3.19
    pkg: musl
    reason: "Example only: temporary reviewed risk acceptance"
    expires: 2026-10-30
  • The default exceptions/allowlist.yaml contains an empty list: no production risk is accepted by the demo.
  • ID is exact, with no wildcard. Optional image/package scopes also match exactly.
  • Reason must be non-empty; expiry must be a real YYYY-MM-DD date.
  • The expiry date is valid inclusively through that UTC calendar day. Expired rules are recorded but do not suppress.
  • Missing configured files, malformed content, unknown fields and duplicate ID/scope entries return exit 2 before Trivy starts.
  • For overlapping valid scopes, the first matching non-expired rule supplies the audit reason.
  • Trivy's implicit ignorefile is disabled so an unrelated .trivyignore cannot silently bypass this policy.

Precedence remains CLI > environment > YAML > defaults. A YAML exception path is resolved relative to its config file; CLI/environment paths are relative to the process working directory. Supported overrides include --exceptions-file and SCANNER_EXCEPTIONS_FILE.

7. Retry and Operational Failure Contract

ConditionBehaviour
Recognized transient network/registry failureDefault initial attempt + at most 2 retries; exponential 1s, 2s backoff
Process timeoutBounded retry; each attempt has the configured Trivy timeout plus a 30s outer deadline
Authentication/authorization error or missing manifestNo retry; operational exit 3
Missing executable, invalid JSON or malformed result shapeFail immediately; never reinterpret as a clean scan
Vulnerability gate blockExit 1; not retried as an operational failure
Artifact write failureAtomic temporary file/replace; exit 3 without partial successful-looking JSON

--retries accepts 0..5; --retry-backoff accepts finite 0..30 seconds, with each delay capped at 30s. CLI/environment/YAML overrides share one validation path. --refresh-db uses the same retry classifier. Enclosing CI timeouts provide a further total bound. Secret-bearing URL userinfo is redacted from error messages; retry notices do not repeat arbitrary registry stderr.

Retry recovery/exhaustion and timeout cases were verified with deterministic controlled subprocess tests. No unperformed live network outage or injected registry failure is represented as real infrastructure evidence.

9. Limitations and Security Boundary

  • Scanning remains OS-package scoped by default. Language dependencies require a deliberate scope change.
  • Allowlist changes are repository policy and need human review. The code does not establish an approver identity or enforce branch protection by itself.
  • A checksum detects changes against a trusted manifest; it is not a digital signature.
  • Exception expiry is checked at scan time. An old approved artifact is historical evidence, not authorization for a future build.
  • Live demo counts can change with the vulnerability database; fixtures make the tests stable.
  • Slack/Jenkins and GitHub use separate secret stores. GitHub Slack secret entry and rotation of the previously exposed webhook require direct account-owner action; no secret is embedded here.

10. Conclusion

Sprint 5 implements governed exception handling without hiding accepted risk, fresh lineage-preserving rescans, and fail-closed reliability controls. Real active/expired policy demonstrations, original artifacts, generated audit reports, repeatable browser evidence and 77 passing tests support the delivered behaviour.
