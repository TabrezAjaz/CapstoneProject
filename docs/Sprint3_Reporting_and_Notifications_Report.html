1. Executive Summary

Sprint 1 established scanning. Sprint 2 enforced it in CI. Sprint 3 makes the results communicable: every scan now produces a versioned artifact, a single canonical report model generates JSON, HTML, and PDF outputs with a SHA-256 manifest, and the same notifier sends severity-aware Slack alerts from GitHub Actions, Jenkins, or a local shell.

Verified outcome: 28 deterministic tests pass; a real scan of alpine:3.19 produced a schema 1.0 artifact with 2 HIGH findings and exit code 1; a single command generated JSON, HTML, and PDF reports that share one report ID and checksum manifest; GitHub Actions run #13 generated the reports inside CI and uploaded a 5,865-byte evidence bundle.

Scanning, presentation, and delivery stay separate. Reporters never invoke Trivy, notifiers never parse raw scan output, and policy decisions remain in scanner/trivy_scanner.py. Slack is the only implemented provider, but Teams or email can implement the same protocol without touching reporting or CI orchestration.

4. Scan Artifact Schema 1.0

FieldPurpose
schema_versionContract version; loaders reject anything else
scan_id, scanned_atUUID and UTC timestamp for traceability
image, summary, findingsImage identity, five-key severity counts, normalized findings
policyfail_on, blocking_findings, passed
scan_optionsSeverities, unfixed handling, package scope, timeout
scanner, sourceScanner versions and sanitized CI metadata

The loader verifies that per-severity counts equal the findings and rejects raw Trivy JSON or legacy files before rendering, so a report can never silently mix formats.

6. Notification Design

  • Immediate run alerts fire only at or above notifications.alert_on (default HIGH).
  • CRITICAL is urgent/red, HIGH action-required/orange, MEDIUM warning/yellow, LOW informational/blue, and a clean summary is green.
  • Daily and weekly summaries are always delivered, including clean and partially failed batches.
  • Messages carry image names, severity counts, policy state, cadence, and the report ID — never every CVE and never the webhook URL.
  • Only a provider-neutral Notifier contract is exposed, so Teams or email can be added later without changing reports or pipelines.

7. Security and Reliability

ControlBehaviour
Secret handlingWebhook read only from SLACK_WEBHOOK_URL environment or CI credential binding; never from YAML, files, logs, or arguments
Endpoint validationHTTPS only, hooks.slack.com/hooks.slack-gov.com, /services/ path, no credentials, no fragment, no non-443 port
TransportRedirects refused, 10-second timeout, bounded payload size, no shell interpolation of the secret
RetriesAt most three attempts with exponential backoff plus jitter for timeouts, 408, 425, 429, and 5xx; honour numeric Retry-After; other 4xx are not retried
Injection safetyHTML autoescaped; scan-controlled values truncated and @channel/@here neutralized
Failure clarityPolicy block (exit 1) stays distinct from operational failure (exit 3) so a broken scanner can never look like a clean image

10. GitHub Actions Integration

The existing gate now captures the scanner exit code without ending the job, generates JSON/HTML/PDF reports, conditionally sends a severity-aware alert, uploads every artifact under if: always(), and only then restores the correct build result.

11. Jenkins Integration

ci/Jenkinsfile adds a Generate Reports stage and an optional Notify Slack stage bound to the slack-webhook-url Secret Text credential. The scanner result is preserved and only restored after reporting and notification, so archived evidence is never lost. Summary builds use ci/Jenkinsfile.summaries.

Agent compatibility fix: the academic agent runs dash, so the first Sprint 3 build failed with exit 127 when shopt and bash arrays were used. The Jenkins stages were rewritten with POSIX globbing; subsequent builds passed on the first attempt.

Two Pipeline jobs share ci/Jenkinsfile.summaries with different cadence parameters and UTC cron triggers, and each run rescans every image in config.yaml.

14. Cost

All Sprint 3 components are open source and run on existing infrastructure: Jinja2 and ReportLab replace commercial PDF services, Slack incoming webhooks are free on the current plan, and the vulnerability database plus CI caching keep repeat runs cheap. Incremental software cost remains ₹0.

15. Troubleshooting and Limitations

SymptomCause and resolution
Unsupported scan artifact schemaA raw Trivy or Sprint 1/2 file was passed. Regenerate artifacts with the current scanner and pass only *-????????.json files.
Notification skippedThe run report is below alert_on. This is intentional; use --always for summaries.
SLACK_WEBHOOK_URL is requiredThe secret is not bound. Set the GitHub secret or the Jenkins slack-webhook-url credential.
Slack step skipped in CIExpected when the secret is absent or the event is a pull request from a fork.
Artifacts missing after some weeksCI artifact retention expires; the report manifest records checksums for long-term traceability.

16. Conclusion

Sprint 3 completes the reporting and notification layer. Vulnerability data is now versioned, validated, rendered into three formats with verifiable checksums, and delivered to the people who need it — without weakening the Sprint 2 gate, and without introducing any paid service, database, or dashboard. Dashboards and historical trend storage remain deliberately out of scope for Sprint 4, and CVE exception handling remains Sprint 5.
